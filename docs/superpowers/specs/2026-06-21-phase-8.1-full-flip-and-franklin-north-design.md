# Phase 8.1 — Full-Scene Kit Flip + Franklin-North Corridor (Design)

**Date:** 2026-06-21
**Status:** Approved (design); pending spec review → implementation plan.
**Branch:** `feat/inked-facade-look`
**Builds on:** `2026-06-21-phase-8.1-kit-into-selection-design.md` (kit wiring + pilot gate). This spec executes the two steps that one **explicitly deferred**: the whole-scene flip (its scope decision #5) and corridor expansion (its Workstream 3).

## Why this spec exists (the traveling-learnings problem)

The 8.0 structural-depth craft (recesses, sills, stoops, fire escapes, cornices, per-family material) was proven on a **4-BIN pilot** and approved by Batu. The risk Batu raised: *don't make us fine-tune every new building.* This spec verifies that the craft **travels automatically** and removes the gate that's currently holding it back.

**Key fact established during design:** the craft is already parametric, not per-building.
- **Material** resolves via `resolveFacadeFamily()` (`src/facadeFamily.js:18`): curated override → pilot map → heuristic over `classifyBuilding` (NYC PLUTO year/class). Every building gets a family with no hand-authoring. The heuristic only asserts the *safe* families (brick / painted-masonry / warehouse); clapboard / brownstone / modern-flat require evidence-bound curated overrides, so we never falsely claim a material.
- **Recesses, street-facing sides, stoops, fire escapes, cornices, window trim** are derived inside `decorateInkedWall` (`src/SceneView.jsx`) keyed off `family` + `storeys` + street-face detection. Family/storey-gated, not per-BIN.

**The gate:** `KIT_PILOT_BINS` (`src/SceneView.jsx:1056`), while non-empty, pins the inked kit to the 4 pilot buildings; everything else still falls through to the old cheap `decorateTypologicalWall`. Emptying it is "the full flip" — and its own comment says it's cleared "after Batu approves the four in-scene," which has now happened.

So learnings travel through the family/storey gates; the flip is what *activates* those gates for every building, and 8.1a is where we *prove* the defaults hold at scale before adding new geometry.

## Scope

Two ordered steps. Step 8.1a must hold before 8.1b.

### 8.1a — The full flip (make learnings travel + prove it at scale)

**Action:** empty `KIT_PILOT_BINS` so the inked kit applies to every kit-eligible building via the heuristic family resolver (asset-less families still degrade honestly to `decorateTypologicalWall` per the prior spec's Option-A fallback — unchanged).

**Validation surface:** the **~92 buildings already loaded** (franklin-milton + greenpoint-east). They flip from the cheap score-line look to the inked kit. We judge:
- **Material correctness** — heuristic families resolve sensibly against PLUTO (Franklin is ~uniform brick-prewar; expect mostly brick, which is correct for the stock). No building wears another material's texture.
- **Recess registration** — windows/doors carve true recesses with sills/lintels, not proud frames, across varied storey counts and bays.
- **Street-facing sides** — the street face(s) get openings/storefront/stoop/fire-escape; party walls and rears stay correctly bare or typological, from all four camera angles.

**The bar:** every fix must be **systematic** (heuristic- or gate-level, affecting a whole family/storey class), **not** per-BIN. `FACADE_OVERRIDES` remains the evidence-bound escape hatch for a genuine exception (e.g. a confirmed brownstone/clapboard), but the *default must be good without tuning*. If a class of buildings looks wrong, fix the gate, not the building.

**Done when:** the existing two blocks render through the kit, the three validation dimensions hold across all four angles with zero new per-BIN overrides (beyond any pre-existing evidence-bound ones), and `npm run verify` is green.

### 8.1b — Franklin-North corridor (Greenpoint Ave → Huron St)

**Action:** apply the proven block recipe (Scaling Log: descriptor + two scripted pulls + ~4 registration lines, no new modules) to a new block extending the scene **north** up Franklin from the existing corner.

- `src/data/blocks/franklin-north.block.json` — descriptor: Franklin St, **Greenpoint Ave → Huron St** (covers Astral Apartments at 184 Franklin and reaches the Eberhard Faber / Kent cluster).
- Run `pull-footprints.mjs` + `pull-storefronts.mjs` → two committed extracts.
- Register in `SceneView.jsx` (imports + block-registry entry + flatMap arg); the `sceneFrame.js` block loop extends the ground run automatically.

**The three new heroes (Brouwerij Lane, Eberhard Faber building, Astral) render typological** in this pass — placed and present, not yet bespoke (they have no field photos; hero promotion is a clean later cycle gated on Batu photos, per the locked 8.1 sequencing). Their `building-tiers` hero flag stays intact so promotion is non-destructive. I confirm each is present in the footprint pull.

**Because 8.1a already flipped the kit on, every new building inherits the inked treatment automatically** — material/recess/street-face resolve from PLUTO + family gates with **no per-building work**. That is the whole point of ordering 8.1a first.

**Done when:** the corridor renders through the kit at scale across all four angles, the `score-block-build.mjs` scorecard passes (storey source-backed %, family mix, storefront count), Astral is present, and `npm run verify` is green.

## Risks & mitigations

- **Heuristic mis-classes a building's material at scale.** Mitigation: the heuristic only emits safe families; a visibly-wrong one gets a *systematic* gate fix or, if genuinely exceptional and evidence-backed, a curated override. Track any override added and why.
- **Flip reveals a recess/street-face gate bug that the 4-BIN pilot didn't exercise** (e.g. unusual storey counts, corner buildings, deep lots). Mitigation: that's exactly what 8.1a is for — caught on trusted existing buildings before new geometry, fixed at the gate.
- **New block surfaces hero/roster overlap** (OSM returns hero businesses in-bbox). Mitigation: the existing hero name + proximity guards and `dedupeByProximity()` carry over unchanged (proven on Block B).

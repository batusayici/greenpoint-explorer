# Phase 8.1 — Wire the Inked Component Kit into Building Selection (Design)

**Date:** 2026-06-21
**Status:** Approved (design); pending spec review → implementation plan.
**Branch:** `feat/inked-facade-look`

## Goal

Route real procedural buildings through the **completed inked component kit**
(`composeInkedFacade` + `assets/inked/<family>-<component>.v1.png`, proven in the
dev-only `?assetkit=` harness) instead of the cheap score-line decoration — but
only where doing so makes a **truthful** material claim. A building renders in the
kit's hand-inked style for its actual material family (brick / clapboard /
brownstone / modern-flat); families without assets, or buildings whose family we
cannot ground, degrade honestly to the existing cheap path. No building ever
wears another material's texture.

This is the rendering core of PLAN.md **Phase 8.1**. Corridor footprint
**expansion is explicitly deferred** to a later pass (decision below).

## Scope Decisions (locked with Batu, 2026-06-21)

1. **Full 8.1 intent**, narrowed to the rendering core this pass — see #4.
2. **Family truth = hybrid.** Heuristic base (marked unverified) + curated per-BIN
   overrides (evidence-bound). Evidence tier tracked per building.
3. **Asset-less fallback = Option A (honest degradation).** Family *with* kit
   assets → kit renderer. Family *without* assets (`painted-masonry`, `warehouse`)
   → existing cheap `decorateTypologicalWall`. Partial families (`modern-flat`,
   no cornice/door-stoop) render the components they have and omit the rest. No
   cross-material substitution.
4. **Spine reach = render what's already loaded.** No new `pull-footprints.mjs`
   run this pass; Workstream 3 is deferred. The kit is proven on buildings already
   in the scene, with a handful of evidence-bound curated entries so at least one
   clapboard and one brownstone building visibly render in their own material.
5. **Pilot gate before full-scene routing.** The kit path is first wired to
   **exactly one building per asset-backed family** (brick, clapboard, brownstone,
   modern-flat = 4 buildings). Batu approves the four in-scene before the selection
   routing is flipped on for the rest of the loaded scene. The whole-scene flip is
   a *separate, gated step*, not part of the initial wiring.

## The key discovery (why this is small)

`decorateInkedWall` (`src/SceneView.jsx:2007`) is **already** the proper
production kit renderer: it composes via `composeInkedFacade`, places
wall/ground/windows/cornice as real wall-by-wall geometry on footprint edges,
and already handles street-face-only decoration, corner miters, party-wall
seams, storefronts and awnings. It is only (a) **hardcoded to `brick-*`
component filenames** and (b) reached **only** for `INKED_FACADE_REAL` buildings
(via the `inkedKit` treatment, gated on hand-authored `inkedParams`).

So the work is: **parameterize that renderer by family**, **synthesize its params
from family resolution** (instead of requiring a hand-authored spec), and **route
asset-backed typological buildings to it**. Heroes (`buildHeroBuilding`) and the
existing `INKED_FACADE_REAL` path are untouched and stay byte-stable.

## Architecture — two workstreams

### Workstream 1 — Family resolution (truth layer)

**New pure module `src/facadeFamily.js`** (Node-importable, no Three.js):

```
resolveFacadeFamily(building) -> { family, evidenceTier }
```

- `family` ∈ `familyList()` (`brick | clapboard | brownstone | painted-masonry |
  modern-flat | warehouse`).
- `evidenceTier` ∈ `"curated" | "inferred-unverified"`.

- `evidenceTier` ∈ `"curated" | "pilot-unverified" | "inferred-unverified"`.

Resolution order:
1. **Curated override (truth).** If `building.bin` is in the evidence-bound
   curated map → that family, tier `"curated"`. This is the **only** path that may
   *truthfully assert* `clapboard`/`brownstone`/`modern-flat`. Ships **empty** this
   pass (no field-verified families yet).
2. **Pilot override (dev).** If `building.bin` is in the pilot map (`KIT_PILOT_BINS`)
   → that family, tier `"pilot-unverified"`. Dev-only family assignments to prove
   the renderers; NOT a truth claim, kept out of the curated file. Consulted only
   while the pilot map is non-empty.
3. **Heuristic base.** Bridge `classifyBuilding(...).materialFamily` → a kit
   family, tier `"inferred-unverified"`:
   | classifyBuilding vocab   | kit family        |
   |--------------------------|-------------------|
   | `brick-prewar`           | `brick`           |
   | `commercial-storefront`  | `brick`           |
   | `painted-masonry`        | `painted-masonry` |
   | `warehouse`              | `warehouse`       |
   (`commercial-storefront` is a *use*, not a cladding — its cladding-above-
   storefront defaults to brick; the storefront band is handled by the existing
   sign/awning system.)

**Curated map data file** `src/data/facade-families/greenpoint-corridor.v0.1.json`,
mirroring the `facade-signatures/` + `signatureContract.js` convention:

```json
{
  "_doc": "Per-BIN curated material-family overrides (evidence-bound). A BIN here asserts its facade material against field evidence; absent BINs fall through to the inferred-unverified heuristic. family must be a member of materialFamilies.familyList().",
  "version": "0.1",
  "families": { "<BIN>": "clapboard" }
}
```

A pure validator `isValidFamilyMap(obj)` (+ test) enforces: every value ∈
`familyList()`; every key a non-empty string. A `npm run verify`-chained check
(extend `scripts/verify-inked-component.mjs` or a sibling) asserts every curated
BIN names a real family **and** that family has kit assets (so we never curate a
building onto a family that can't render).

### Workstream 2 — Render wiring

**Kit coverage (single source of truth for "what can render").**
A committed manifest `src/data/materials/kit-coverage.v0.1.json` mapping each
family → the component cells whose `assets/inked/<family>-<component>.v1.png`
file exists today (`brick`: all; `clapboard`: wall/cornice/window/door-stoop/
weathering; `brownstone`: wall/cornice/window/door-stoop/weathering/ground;
`modern-flat`: wall/window/weathering/ground). A verifier (chained into
`npm run verify`) keeps it honest against `assets/inked/`. Pure accessors:
`familyHasKit(family)` (has a `wall`), `kitHas(family, component)`.

**Parameterize `decorateInkedWall`.** `params` gains `family` (default `"brick"`
so existing `INKED_FACADE_REAL` buildings are byte-stable). Replace every
hardcoded `"brick-…"` filename with `kitFile(family, component)`:
- returns `${family}-${component}.v1.png` when `kitHas(family, component)`;
- returns `null` otherwise → **caller skips drawing that layer** (modern-flat
  draws no cornice; no brick substitution).
The full-height wall (all faces, incl. side/rear) uses the family's `wall`
(guaranteed present because a building only reaches this path when
`familyHasKit`).

**Synthesize kit params** — new pure helper, e.g.
`buildKitFacadeParams(building, family)` (Node-testable) → the `params` object
`decorateInkedWall` expects, built from family + `classifyBuilding`:
- `family`
- `tint`: `MATERIAL_WALL_TONES[family]` snapped via the existing color binding.
- `storeys`: `classifyBuilding(...).storeyCount`.
- `storefront`: a category storefront descriptor when
  `groundFloorUse === "commercial"`, else `null` (stoop/ground band path).
- `corner`: reuse the existing corner-detection used by the inked path.

**Selection routing — `selectTreatment`.** Inputs gain the building's resolved
family + `familyHasKit`. New logic (existing branches unchanged):
1. `building.isHero && building.edges` → `hero`.
2. `inkedParams` (INKED_FACADE_REAL) → `inkedKit` *(unchanged path)*.
3. typological-eligible (`fromBlockExtract` or within `contextRadius`):
   - resolved `familyHasKit(family)` → **`inkedKit`** (kit-driven, params
     synthesized in WS2);
   - else → `typological` (cheap `decorateTypologicalWall`).
4. otherwise → `graybox`.

**`buildBuildings` data flow.** Where `inkedParamsPre` is computed today, also
resolve the family for non-inked-real buildings and synthesize kit params so the
`inkedKit` branch (`SceneView.jsx:1414`) renders them. `evidenceTier` is written
to `body.userData` (metadata only — no Scene-visible difference this pass; a
Debug overlay is out of scope, see Non-Goals).

**Rollout switch (the pilot gate, decision #5).** A single committed constant
`KIT_PILOT_BINS` — a **map of BIN → family** (the dev pilot-override consulted by
`resolveFacadeFamily` step 2) — gates the *new* routing in `selectTreatment` /
`buildBuildings`:

```js
// Dev-pilot family assignments (tier "pilot-unverified"). One per asset-backed
// family, on real loaded block-extract BINs. NOT truth — emptied at full flip.
const KIT_PILOT_BINS = {
  "3064677": "brick",       // 3-storey 1864 rowhouse — genuine heuristic brick
  "3064605": "clapboard",   // 3-storey 1868 rowhouse — pilot-unverified
  "3064541": "brownstone",  // 4-storey 1896 C1        — pilot-unverified
  "3398449": "modern-flat", // 4-storey 2014           — pilot-unverified
};
```

- **Pilot mode** — `KIT_PILOT_BINS` non-empty: the kit path (step 3 below)
  applies **only** to those BINs; every other typological building keeps the
  cheap `decorateTypologicalWall`. → **STOP, Batu approves the four in-scene.**
- **Full mode** — after approval, `KIT_PILOT_BINS` is emptied in a separate
  commit so every kit-eligible building routes through the kit. **Consequence
  (truthful):** with the curated truth map empty, the heuristic only yields
  `brick` (+ asset-less painted-masonry/warehouse → cheap path), so full mode
  lights up the **brick majority** of the corridor through the kit; clapboard/
  brownstone/modern-flat kits stay ready-but-unused until evidence-curation (a
  follow-on truth task). This is the only code change between the two steps.

The existing `INKED_FACADE_REAL` and hero paths ignore `KIT_PILOT_BINS`
entirely (they are byte-stable in both modes).

### Workstream 3 — Spine expansion — DEFERRED

No footprint pull this pass (decision #4). Documented as the immediate follow-on
in PLAN.md; new buildings will flow through WS1+WS2 unchanged when pulled.

## Data flow (one building, kit path)

```
footprint record
  └─ classifyBuilding ──────────────► { storeyCount, materialFamily(use-vocab), groundFloorUse }
  └─ resolveFacadeFamily ───────────► { family (kit-vocab), evidenceTier }
        └─ familyHasKit(family)? ─ no ─► decorateTypologicalWall (cheap path)
                                  └ yes ─► buildKitFacadeParams ─► params{family,tint,storeys,storefront,corner}
                                            └─ decorateInkedWall (per-edge)
                                                 └─ kitFile(family, comp) → draw or skip
```

## Modules & boundaries

| Unit | Responsibility | Depends on |
|------|----------------|------------|
| `facadeFamily.js` | building → `{family, evidenceTier}` | `buildingTypology`, `materialFamilies`, curated map |
| `facade-families/greenpoint-corridor.v0.1.json` | evidence-bound per-BIN overrides | — |
| `materials/kit-coverage.v0.1.json` + accessors | which `(family,component)` PNGs exist | `assets/inked/` (via verifier) |
| `buildKitFacadeParams` (pure) | family → `decorateInkedWall` params | `buildingTypology`, palette tones |
| `decorateInkedWall` (modified) | per-edge kit geometry, family-parameterized | `composeInkedFacade`, `kitFile` |
| `selectTreatment` (modified) | treatment kind incl. kit-eligibility | family + coverage |

Each pure unit is independently Node-testable; only `decorateInkedWall` /
`buildBuildings` touch Three.js.

## Testing

- `facadeFamily.test.mjs`: curated override wins; each heuristic vocab maps
  correctly; tier is `curated` vs `inferred-unverified`; unknown family in a
  curated map is rejected by `isValidFamilyMap`.
- `buildKitFacadeParams` test: tint from `MATERIAL_WALL_TONES`, storeys from
  classify, storefront flag from `groundFloorUse`.
- coverage test: `kitHas` true/false per cell; `familyHasKit` false for
  `painted-masonry`/`warehouse`; `modern-flat` lacks `cornice`.
- coverage verifier vs `assets/inked/` (chained into `npm run verify`).
- curated-map verifier: every BIN's family is real **and** has kit assets.
- **Visual proof = the pilot gate (decision #5).** With `KIT_PILOT_BINS` seeded to
  one BIN per asset-backed family (the four real BINs above, tier
  `pilot-unverified`), load the scene and capture a screenshot **per pilot
  building** (brick,
  clapboard, brownstone, modern-flat). Confirm each reads correctly in its own
  material, that brick/`INKED_FACADE_REAL`/hero buildings are unchanged (hero
  corner byte-stable), and no console errors. **STOP — Batu approves the four
  before the full-mode flip.** The flip (empty `KIT_PILOT_BINS`) gets its own
  re-screenshot of the broader scene.

## Truth rules

- `evidenceTier` is recorded per building; `inferred-unverified` families are a
  marked inference, not an asserted fact (CLAUDE.md truth rule). A factual review
  pass before public release can audit/curate them.
- Only the **curated** map may assert clapboard/brownstone/modern-flat — those
  require field evidence, consistent with the facade-truth-pipeline model.

## Non-Goals (this pass)

- No corridor footprint expansion (deferred — decision #4).
- No `painted-masonry` / `warehouse` asset generation (Phase 7 carryover).
- Signature layer stays **define-only** — not applied to the renderer.
- No Debug-mode evidence-tier overlay (metadata only; can be a later pass).
- Heroes and `INKED_FACADE_REAL` render paths unchanged (byte-stable).

## Risks

- **Nothing non-brick renders if no curated BIN sits in the loaded set.** Mitigated
  by authoring a handful of evidence-bound curated entries for already-loaded BINs
  as part of the visual-proof step.
- **`buildKitFacadeParams` drift from `INKED_FACADE_REAL` params shape.** Mitigated
  by `family` defaulting to `"brick"` and reusing the existing param fields; the
  hand-authored path is the contract the synthesized path mirrors.
- **Coverage manifest drift** as families fill in. Mitigated by the
  `npm run verify` coverage check against `assets/inked/`.

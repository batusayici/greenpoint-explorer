# Phase 8.1 — Full-Scene Kit Flip + Franklin-North Corridor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Activate the inked component kit for every kit-eligible building (the "full flip"), prove the 8.0 craft travels at scale without per-building tuning, then extend the scene north up Franklin (Greenpoint Ave → Huron) via the proven block recipe.

**Architecture:** Two ordered steps. 8.1a empties `KIT_PILOT_BINS` so `resolveFacadeFamily` + `buildKitFacadeParams` + `decorateInkedWall` apply to all `fromBlockExtract` buildings via their PLUTO-derived family; validation runs on the ~92 already-loaded buildings and any fix is systematic (gate-level), never per-BIN. 8.1b adds one new block (descriptor + two scripted data pulls + ~4 registration lines, no new modules); it inherits the flipped kit automatically.

**Tech Stack:** React 19 + Three.js + Vite; Node ESM verifier/pull scripts; `node --test` for unit tests.

## Global Constraints

- **Systematic fixes only in 8.1a.** Any correction to material/recess/street-face must be at the heuristic/gate level (affecting a whole family/storey class). `FACADE_OVERRIDES` is the only per-BIN channel and is reserved for evidence-bound exceptions; record any override added and why.
- **No material lie.** The heuristic family resolver may only emit `brick` / `painted-masonry` / `warehouse`. `clapboard` / `brownstone` / `modern-flat` require a curated `FACADE_OVERRIDES` entry. No building wears another material's texture.
- **Palette is a no-miss.** Every scene color resolves to a token in `src/visualSystem/palette.js`; the 6.2.3 conformance gate (`npm run verify:conformance`) must stay green.
- **`npm run verify` green after every task** (currently 147 tests + conformance + visual + components + stories + kit-coverage + overrides).
- **Heroes untouched.** `buildHeroBuilding` and the `INKED_FACADE_REAL` path stay byte-stable. The 3 new heroes (Brouwerij/Eberhard Faber/Astral) render typological this cycle; their `building-tiers` hero flag is left intact.
- **Commit when a coherent step lands and builds; never push without Batu.**

## Task 2: Validate the flip at scale on existing blocks (8.1a)

This is a **validation + systematic-fix checkpoint**, not a code-first task. The deliverable is: the ~92 existing buildings render correctly through the kit across all four angles, with any fix made at the gate level. Sub-fixes (if any) are TDD'd against the relevant pure module.

**Files:**
- Read/observe: live preview of the existing scene.
- Modify (only if a systematic gap is found): `src/facadeFamily.js`, `src/buildKitFacadeParams.js`, or `src/facadeDepthGates.js` + matching `.test.mjs`.

- [ ] **Step 1: Start the preview and load the scene**

Run the dev server (preview_start) and open the Scene at the default angle.

- [ ] **Step 2: Inspect material correctness across the two blocks**

Rotate through all four angles. For each visible block building confirm:
- the wall material reads as its family (Franklin is ~uniform brick-prewar → expect mostly brick — correct, not a bug);
- no building wears another material's texture.
Record any building whose family is visibly wrong with its BIN and the PLUTO `yearbuilt`/`bldgclass` driving it.

- [ ] **Step 3: Inspect recess registration**

Confirm windows/doors carve true recesses (sill + lintel, inward reveal), not proud frames, across the range of storey counts and bay widths present. Note any storey/bay class where the recess gate misfires.

- [ ] **Step 4: Inspect street-facing sides from all four angles**

Confirm the street face(s) carry openings/storefront/stoop/fire-escape and that party walls + rears stay correctly bare/typological. Note any building showing openings on a party wall or a blank street face.

- [ ] **Step 5: For each finding, classify systematic vs. exceptional**

- **Systematic** (a whole family/storey/bay class is wrong) → fix the gate. Write a failing test in the pure module's `.test.mjs` first (e.g. `facadeDepthGates.test.mjs` asserting `wantsStoop(family, storeys)` for the misfiring class), make it pass, then re-observe.
- **Exceptional + evidence-backed** (one genuinely-different building, e.g. a real brownstone) → add a `FACADE_OVERRIDES` entry with a one-line evidence note. This is the only per-BIN channel.
Do NOT add per-BIN tuning to make a systematic problem disappear.

- [ ] **Step 6: Re-run full verify after any fix**

Run: `npm run verify`
Expected: green. Repeat Steps 2–6 until the three dimensions hold with no new per-BIN entries beyond evidence-bound ones.

- [ ] **Step 7: Capture proof + commit**

Take an iso screenshot at two angles showing the flipped existing blocks. Commit any systematic fixes:

```bash

git commit -m "fix(phase-8.1a): <systematic gate fix from scale validation>"   # only if fixes were needed
```

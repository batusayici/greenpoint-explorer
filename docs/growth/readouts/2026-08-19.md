## Calibration log

**The lesson from PR #42, stated plainly:** a Tuesday routine that branches
from `main` and then rewrites `gtm-state.json` wholesale will silently revert
any decision ratified between its branch point and its run, if that PR is
merged without checking. `gtm-state.json` caught its own defect this time
(the `pr42` and `routine-clobber` entries) — which is the system working, but
only because Batu read the state file before merging rather than after.

**One standing instruction proposed, appended to SKILL.md below:**

> **(proposed 2026-08-19, cycle 6 — pending ratification.)** Before writing
> `gtm-state.json` in step 4.5, read the current file on `main` and diff it
> against the branch's copy. If any field this cycle doesn't own has changed
> since the branch point, re-branch from current `main` rather than merging
> the stale copy forward — do not let a PR's age become a silent revert.
> This is what caused PR #42 to propose reverting D1–D6.

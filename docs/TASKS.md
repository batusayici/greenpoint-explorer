## Reusable Visual Batch Acceptance Checklist

Apply this checklist to every future visual batch before reporting completion:

- The batch references `docs/VISUAL_ARTIFACT_STANDARDS.md`.
- The intended Batu decision is stated.
- The intended fidelity level is stated: Level 0 text brief, Level 1 diagram/blockout, Level 2 style tile/component proof, Level 3 static style frame, or Level 4 production/prototype asset.
- The intended artifact class, required output format, format rationale, and SVG allowed/disallowed status are stated before generation.
- The artifact format matches the decision stage: SVG/ASCII/markdown for blockouts, composition planning, and governance review; high-fidelity PNG/JPG for style frames, raster production proofs, final visual-direction candidates, and art-direction approval artifacts unless Batu explicitly requests SVG.
- Batu can make the intended decision from the artifact itself without imagining missing fidelity.
- Variants are materially different in decision-relevant ways, not just color or minor decoration changes.
- Storefront, UI, emotional, composition, and local-specificity evidence is visible at the promised fidelity level.
- Verified, symbolic, placeholder, fictionalized, omitted, and unresolved elements are labeled clearly enough for review.
- Truth/source constraints remain mandatory and are not used as an excuse for generic visuals.
- Codex completed the self-audit template before delivery.
- Codex did not use checklist compliance to pass an artifact whose format is invalid for the intended decision.
- If the artifact fails the self-audit, Codex revised it before reporting completion.
- No blocked app, tooling, production-art, public-interface, or architecture work was introduced.
